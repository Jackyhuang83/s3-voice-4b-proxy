## 2. P0-0 先行的成熟度与适配准入门槛

1. **成熟度必须与技术适用度分开评分**：项目创建/最近代码活动、多个维护周期与 Release、Issues 反馈与关闭质量、独立使用/真实板测、自动化回归、许可证可审计。Stars/Forks 是补充信号，不能仅以 Stars 排名替代技术审查。没有数据的项目必须标 UNVERIFIED。
2. **功能及安全硬门槛（任何一项缺证据不得将项目指定为整机主架构）**：ESP32-S3/IDF6.1、APSTA 与小智单 Wi-Fi owner、无需破坏原语音/LCD/OTA、可信出站 SS2022/VLESS 或清晰的复用接口、TLS 证书验证、IPv6-only VPS、AP DNS 防泄漏与 Fail-Closed、可撤销 hooks、8 MiB PSRAM/内部 RAM 资源界限。
3. **按功能选模块，不强行整仓移植**：先核对官方 ESP-IDF/ESP-NETIF/lwIP 与 ESP-IoT-Bridge（官方也会独立 init Wi-Fi、patch lwIP，不能盲拷 app_main）；再比较 martin-ger 长期维护 NAT/防火墙及其它真实透明 TCP 方案；NOAIC 和 yanxke 降为待验证的实验候选，不因 CI 通过而自动成为首选。
4. **拦截与回退必须分别论证**：停止 Hook 不等于 fail-closed；AP 开启时须能证明无直连 NAT 逃逸。Wi-Fi owner 的权限边界、原版 SDK 补丁范围、软断开/任务回收必须有可自动验证的测试。
5. **未有成熟的完整实现时的处理**：书面列出不可满足的部分、是否存在经验证的最小模块组合及剩余风险；在用户批准任何重大目标/风险调整前，不启动 P1。禁止利用“易写”作为自行开发路由器核心的理由。
