# R2 · S3-Voice 4B Proxy 重构总路线图（GDGS）

状态：**R2-P0-1 #16 与 P0-2 #17 均已合并并通过原版 CI；R2-P0=100%、整体=10%；正在实施 R2-P1-1 源码直接移植，未合并前不计分。**。旧版 main 和 PR #1–#14 均保留为不可破坏的历史参考；PR #15 不再作为 R2 开发基线。旧版“90%”为历史 PR 管理口径，**不自动继承**到新架构；真实 4B 产品验收尚未通过。

## 0. 不变需求与不能牺牲的功能

目标板：微雪 ESP32-S3-Touch-LCD-4B（N16R8），**原版 78/xiaozhi-esp32 小智语音、双麦/音频、480×480 LCD、配网和 OTA 继续工作**。小智自身以 STA 连接既有 Wi-Fi，保留到 IPv4/IPv6（包括 IPv6-only VPS）的出站能力。另提供最多两客户端的 WPA2 下游 AP、仅 IPv4 TCP 透明转发，节点 SS2022 或带**严格服务器证书和 SNI/主机名验证**的 VLESS/TLS。下游 DNS 经加密代理，缺节点、认证错误、上游断线和用户关闭时必须阻断受保护的代理流量，不能直连兜底。不得转发互联网 UDP/QUIC、不得开启下游 IPv6、不得引入 HY2、Snell、Reality、F50 或 D4G-Pocket 功能。

复用优先级：**现成可验证代码 > 官方组件 > 少量适配胶水 > 无替代时才自研**。对每项新增代码必须记录上游现有接口、为什么不能原样移植、最小改动及随源测试。不得为了“看起来更完整”再写一套流表、socket 调度器、DNS、AP 管理器。

## 0.1 用户三项目标：开发交付的不可让步优先级

**目标一：速度快，成熟代码直接移植。** P0-2 必须先在固定上游提交复现作者自带测试与编译，再选出可直接复制的文件/调用关系；保留原注释、许可证、API 和测试，避免按上游功能描述重新写实现。每个改动给出 `上游文件 SHA → 实际移植 SHA → 最小 diff`。若无法直接移植，必须用源码/接口测试证明阻断点，优先包装器或替换单一边界接口，而不是自写新的流表、重写器、调度器。未形成此矩阵不得开始 R2-P1。

**目标二：尽量减少用户后续实机测试。** 直接继承并运行上游主机回归，另外用 CI 完成 SDK 兼容、协议对照、异常密钥、断网、DNS 无泄漏、资源/并发限制与完整小智 4B 镜像编译。由 AI 负责 GitHub 排障和原 PR 修复。**同一轮实机集中验收**：保留小智语音/LCD/触控、一个手机连接 AP（分别选 SS2022 与 VLESS）、故障时阻断与正常恢复、重启后可回到原版小智功能。一次不够的部分先依据日志/CI 排障，不能每改一行就要求用户刷写或盲测。上游板上数据只能证明其**原硬件和原上游**，不能代替小智共存/协议适配后的必要终验。

**目标三：保护已有语音助手，适配代码最少并有退路。** 原小智 `app_main`、音频链路、LCD、触控、配网、OTA、分区及现有 Wi-Fi owner 为保护基线；新增网关以**默认关闭、可独立启停**的最小组件嵌入。禁第二套 Wi-Fi 初始化、禁自动擦 NVS、禁生产固件自动替换。硬件操作前必须验证稳定版本备份、恢复路径与失败回退；关闭网关能恢复原小智语音/Wi-Fi，不得需要重新刷固件才能关闭。所有阶段按源证实、上游回归、集成 CI、设备实测分别标注。

**三项目标的否决规则：** 只要存在已验证的可复用模块而未提供不能复用的具体证据，禁止提交同功能自研代码；若适配需要改动小智音频、LCD 或 Wi-Fi 所有权，暂停并改选低侵入方案；如果某次提交只能靠频繁让用户刷机来排障，先补自动化测试后再继续。**优先缩小改动和用户参与，不以写代码数量或 CI 次数衡量进度。**

## 2. 固定选型评价与 P0 否决门槛

对两个主候选用相同评估表：**模块独立性（20）、官方 SDK/小智侵入性（20）、原版可复现测试（20）、错误/断线/并发控制（20）、双协议适配难度（10）、8 MiB PSRAM 与音频/LCD 资源余量（10）**，共 100 分；每项必须提供代码和 CI 证据，不凭 GitHub Star 或 README 简介打分。P0-1 仅收集事实，**P0-2 才可给出经复现的分数和选型**。

候选 A：`noaic/esp32-socks5-gateway` MIT，真实 ESP32-S3 N16R8 原版测试记录、独立 `flow_table.c` / `packet_rewrite.c` / `ap_clients.c` 与 `socks_relay.c`；其 `tcp_poc.c` 依赖**定点修改 ESP-IDF 6.1 的 ip4.c**，不能不经适配就塞入小智。SOCKS5 握手/UDP 不是本项目需要的加密传输。

候选 B：`yanxke/ESP32-VPN-Transparent-Proxy-Router` MIT，已有 P1 所用的 `transparent_tcp.c/.h` 和输入 Hook，适配面窄；但主要任务管理、DNS 和 Wi-Fi 在庞大 `main.c`，直接整份复制会与小智的 Wi-Fi owner 冲突。两套候选都**禁止整套主程序替换小智**。

既有 rlog AES-GCM SS2022、ESP-TLS/VLESS 是协议候选资产，不因重启路线图自动废弃，也不能因历史 CI 成功自动通过新端到端验证。

P0-2 的决策必须先解决：哪套项目的现有测试最能复现、是否可以仅复用模块、不修改小智音频/Wi-Fi 所有权、是否能避免 patch ESP-IDF 6.1 的核心 ip4.c，及两路加密 TCP 接口是否可以复用原始事件循环。如果两个候选都做不到，则记录被证明的阻断项并选**最少新代码**的组合方案；不得以“兼容性”作为不经比较的自研理由。

**P0-2 经源码审计的选型：**NOAIC 为**唯一数据平面**、yanxke 保留为 Hook 回退备选；不移植任一完整路由器 app_main，不启用双拦截器。完整证据见 [R2-P0-2-DECISION](R2-P0-2-DECISION.md) 与 [复现日志](R2-P0-2-REPRODUCTION.md)。这是源码选型而非产品实机 PASS。
